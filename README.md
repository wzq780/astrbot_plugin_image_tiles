# 识图切块 · astrbot_plugin_image_tiles

> 大图先切成块再送给模型，把可用细节放大 4~9 倍。

![识图切块](logo.png)

## 它解决什么问题

很多多模态接口对图片有硬上限：

| 环节 | 上限 |
| --- | --- |
| DeepSeek 视觉 | 每张图约 1300×1300 有效像素，最多 1024 token |
| AstrBot 图片预处理 | `provider_settings.image_compress_options.max_size`（默认 1280），单图 512 KB |

也就是说，一张 4000×3000 的手机照片，先被压到 1280，再被模型压到约 1300，
最后能看清的其实就是一张缩略图。**屏幕上的数字、远处的门牌、纸张角落的小字，
在这个尺度下全都糊成一团。**

本插件不改变任何上游设置，只在请求发出前多做一步：

```
原图 4000×3000  →  2×2 切开  →  4 块各 2000×1500  →  每块缩到 ≤1200px、≤420KB
                 →  4 块一起送进模型（合计细节量 ≈ 原图的 4 倍）
```

## 效果

- 截图里的聊天记录、表格数字、报错信息：从「大概能猜到」变成「能逐字读出来」
- 商品价签、门牌、路牌、书页：小字可辨认
- 表情包、界面元素、图片角落的物件：能说出具体是什么
- 一张图里有多个人物或物件时：能分别描述各自的样子，而不是混成一句「一张图片」

> 代价是 token：2×2 大约相当于看 4 张图，3×3 相当于 9 张。请按需开启。

## 配置

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关 |
| `grid` | `2` | `2` = 2×2 四块；`3` = 3×3 九块（字特别小时用） |
| `max_images` | `2` | 一次最多切几张，其余原样发送 |
| `min_side_to_tile` | `700` | 最长边小于此值的图不切（切了只会更糊） |
| `tile_max_side` | `1200` | 每块缩放后的最长边 |
| `tile_max_bytes_kb` | `420` | 每块体积上限，超过自动降 JPEG 质量 |
| `jpeg_quality` | `88` | 起始 JPEG 质量，文字图建议 ≥90 |
| `overlap_percent` | `0` | 相邻块重叠比例，防止正好切在一行字中间 |
| `process_inline_images` | `false` | 是否连已转成 base64 的图片也切 |
| `note_enabled` | `true` | 是否追加「这些块拼起来才是同一张图」的说明 |

## 指令

| 指令 | 作用 |
| --- | --- |
| `/识图切块` | 查看当前配置与最近一次处理结果 |

## 行为细节

- **先按 EXIF 摆正**：手机竖拍的方向信息在 EXIF 里，不转正会切歪。
- **小图不动**：低于 `min_side_to_tile` 的图保持原样，不浪费 token。
- **逐块限流**：先按最长边缩放，再按字节数降质量，两块上限都不越界。
- **分组说明**：多张图时会写清「图 1 是第 1~4 块、图 2 是第 5~8 块」，
  避免模型把两张图的局部混在一起。
- **失败即退让**：取图失败、图片解不开、任何异常，都保留原图，不影响本轮对话。

## 常见问题

**Q：开了以后模型说「这是一张小图/被切开了」？**
A：把 `note_enabled` 保持开启。它在每条请求里都会说明这些块属于同一张图。

**Q：报「图片过大」？**
A：把 `tile_max_bytes_kb` 调到 300，或把 `grid` 调回 2。

**Q：切了没效果？**
A：先 `/识图切块` 看「最近一次」有没有真的切。如果一直显示「图片太小」，
说明你的上游已经把图压到 700px 以下了，此时需要先调大
`provider_settings.image_compress_options.max_size`。

**Q：和别的识图插件冲突吗？**
A：本插件在 `on_llm_request` 的 priority=1 阶段最早执行，替换的是
`req.image_urls`。若还有别的插件也改写同一字段，后执行的会覆盖前一个。

## 开发与致谢

切块思路来自「视觉模型的 token 预算按像素面积分配」这一事实：
在单图预算不变的前提下，把面积摊给多张子图，就能让每块获得更高的有效分辨率。
